Kubernetes 기반 LLM 서비스 관측성 플랫폼

2026-05 – 2026-064인 팀 · 로컬 MVP

로컬 Kubernetes(kind) 환경에서 LLM/RAG 서비스의 검색·모델 호출·오류를 요청 단위로 연결한 관측성 MVP입니다. 지표와 trace, 알림을 함께 확인해 지연과 실패 원인을 추적합니다.

프로젝트 저장소 ↗
기여와 역할

문제 정의, 기존 솔루션 비교, 로컬 SLM 활용 검토와 검증 시나리오 설계를 맡았습니다. MVP 구현과 반복 실행 결과는 팀 공동 작업입니다.

결과

팀은 5개 시나리오를 각 10회 실행해 주입한 지연과 오류가 해당 관측 구간에 나타나는 것을 확인했습니다.

사용 기술
Kubernetes (kind)OpenTelemetryPrometheusGrafanaJaegerFastAPIDockerOllama
목차대표 자료요청 단위 실행 추적반복 가능한 로컬 검증 범위 설정관측 데이터의 활용 경로관련 자료

요청 단위 실행 추적

전체 응답 시간만으로는 검색·모델 호출·후처리 중 어디에서 지연되는지 구분하기 어렵습니다.

팀은 Chat UI의 request_id와 trace_id를 대시보드·Jaeger·오류 알림에 연결해 한 요청의 실행 단위를 확인하는 MVP를 구현했습니다.

  • 검색과 모델 호출의 span 및 소요 시간 비교
  • 요청별 토큰·비용 지표 확인
  • 오류 상태를 유지한 추적과 Discord 알림 연결

반복 가능한 로컬 검증 범위 설정

외부 API 비용과 호출 제한에 덜 영향을 받으며 반복 실험할 수 있도록 로컬 소형 언어모델(SLM) 활용을 검토했습니다. 정상 요청, 검색 지연, 모델 지연, 토큰 증가, 오류의 5개 검증 시나리오를 설계했습니다.

구현에는 AI 에이전트를 활용했습니다. 팀과 함께 각 시나리오를 10회 실행하고 request_id와 trace_id를 기준으로 요청 지표, 실행 추적, 오류 알림이 연결되는지 점검했습니다.

  • 검색 지연과 모델 지연: 지연을 주입한 단계의 span과 소요 시간 확인
  • 정상 요청과 토큰 증가: 요청별 지표 변화 비교
  • 오류 요청: 추적 정보 유지와 알림 연결 확인

관측 데이터의 활용 경로

FastAPI API 계측에서 수집한 요청 정보가 Prometheus 지표와 Jaeger 추적으로 이어지고, 실패 요청은 알림으로 연결됩니다.

팀은 단일 요청을 기준으로 지연·토큰·오류를 함께 확인하는 MVP를 구성했습니다. 담당 범위는 문제 정의와 솔루션 비교, 개발 범위 검토 및 검증 시나리오 설계입니다.

  • OpenTelemetry 기반 요청 흐름 계측
  • Prometheus·Grafana 지표와 Jaeger trace 결합
  • SLM·Discord 기반 알림 흐름 구성
