  • OpenTelemetry 기반 요청 흐름 계측
  • Prometheus·Grafana 지표와 Jaeger trace 결합
  • SLM·Discord 기반 알림 흐름 구성
04문제 해결

문제 해결과 검증

전체 응답 시간에서 지연 발생 구간으로

문제

  • 전체 응답 시간만으로 검색·모델 호출·후처리 중 지연 구간 구분 어려움

접근·팀 구현

  • 팀 구현: Chat UI의 request_id·trace_id를 대시보드·Jaeger·오류 알림에 연결
  • 한 요청의 실행 단위를 확인하는 MVP
  • 검색과 모델 호출의 span 및 소요 시간 비교
  • 요청별 토큰·비용 지표 확인
  • 오류 상태를 유지한 추적과 Discord 알림 연결

5개 시나리오로 관측 결과 반복 검증

검증 설계

  • 외부 API 비용·호출 제한의 영향을 줄인 반복 실험을 위해 로컬 SLM 활용 검토
  • 정상 요청·검색 지연·모델 지연·토큰 증가·오류의 5개 검증 시나리오 설계

검증 결과

  • AI 에이전트 활용 구현 · 팀과 각 시나리오 10회 실행
  • request_id·trace_id 기준 요청 지표·실행 추적·오류 알림 연결 점검
  • 검색 지연과 모델 지연: 지연을 주입한 단계의 span과 소요 시간 확인
  • 정상 요청과 토큰 증가: 요청별 지표 변화 비교
  • 오류 요청: 추적 정보 유지와 알림 연결 확인

성과와 확인 범위
