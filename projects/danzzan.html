서비스 개요 및 담당 역할

학생은 축제 정보와 예매를 여러 채널에서 확인하고, 운영진은 재학생 확인과 현장 배부를 처리해야 했습니다. 4인 팀이 총학생회와 요구를 정리하며 축제 정보 탐색·예매·입장 업무를 연결하는 웹앱을 만들었습니다.

팀은 기능 단위로 역할을 나눠 각자 화면과 서버를 함께 개발했습니다. 초기 요구사항 정리부터 React/TypeScript와 Spring Boot 기능 개발, NHN Cloud 배포, 운영 모니터링에 참여했습니다. 구현에는 Codex를 활용하고 정책과 이용 흐름을 판단한 뒤 직접 동작을 확인했습니다.

NHN Cloud에 백엔드와 프론트엔드, 로드밸런서, Object Storage를 구성하고 인증서를 적용해 공식 도메인으로 배포했습니다. 배포 이후에도 운영 로그와 사용자 의견을 확인하며 기능을 개선했습니다.

이전 서비스 주소는 https://danfesta2026.yaaksok.com/입니다. 현재 서버 운영은 종료했으며, 서비스를 고도화해 2026년 11월 다시 배포할 계획입니다.

01. 네이버페이 협업 범위 및 가입·입장 연계

봄축제 운영에 적용

축제를 한 달 앞두고 네이버페이의 얼굴인증 입장 서비스와 협업이 제안됐습니다. 기존 예매 기능을 유지하면서 정해진 일정 안에 입장 연계를 준비해야 했습니다.

로그인 API를 새로 연동하는 대신, 단짠에서 예매를 진행하고 가입 시 수집한 네이버 아이디를 예매자 명단으로 전달하는 방안을 제안했습니다. 협력사의 역할과 일정상 제약을 확인한 뒤 팀과 범위를 정했습니다.

동일한 네이버 아이디로 양일을 예매해도 날짜별 입장 권한은 다를 수 있었습니다. 명단 처리 기준과 수정분 전달 범위를 확인하고 전체 명단을 대조하는 방식으로 합의했습니다. 가입 흐름에는 안내·입력란·개인정보 동의를 반영했습니다.

학과 학생들에게 실제 가입을 진행해보도록 요청하고 예매자 명단 추출을 시험했습니다. 봄축제에서 페이스사인 입장이 실제 운영됐으며, 관리자 화면으로 예매 정보를 조회하고 현장에서 팔찌도 배부했습니다.

02. 회원 탈퇴 정책 검토 및 이용 흐름 설계

기존 운영 기간에 배포 · 실제 이용 확인

회원 탈퇴를 구현할 때 Codex는 미사용 티켓이 있으면 탈퇴를 막는 방안을 제안했습니다. 티켓을 포기하고 탈퇴하려는 사용자는 선택할 수 있어야 한다고 판단해 정책을 수정했습니다.

탈퇴하면 보유 티켓을 사용할 수 없다는 안내를 제공하고, 티켓 포기 동의 후 최종 탈퇴 의사를 다시 확인하도록 흐름을 정했습니다. 구체적인 처리 대안과 코드 구현은 Codex의 도움을 받았습니다.

테스트 계정을 직접 탈퇴하며 의도한 기능과 이용 흐름을 확인했습니다. AI에는 API 응답·인증 상태·재로그인·운영 수량까지 확인하도록 요청했습니다.

회원 탈퇴 기능은 운영 서비스에 배포됐고 실제 이용자의 탈퇴에 사용됐습니다.

03. 운영진 권한 관리 기능 고도화

권한 관리 구현 완료 / 2026년 11월 고도화 서비스 재배포 예정

초기 운영에서는 스태프에게 관리자 권한을 줄 때마다 운영 DB의 권한 정보를 직접 수정했습니다. 운영진이 바뀔 때마다 개발자를 거쳐야 했던 절차를 후속 개선 과제로 삼았습니다.

Notion의 접근 권한 방식에서 아이디어를 얻어 팀과 이메일 초대·관리자 역할만 두는 방식 등을 검토했습니다. 권한 검토의 핵심 기준은 담당 업무에 필요한 범위만 허용하는 것이었습니다. 팀은 최고관리자가 가입된 회원을 학번으로 찾아 매니저로 지정하고, 운영 관리와 티켓팅 권한을 나눠 부여하는 구조를 선택했습니다.

역할별 화면·기능 범위를 정하고 Codex에 계획 수립, 검수, 구현을 나눠 요청했습니다. 메뉴 표시뿐 아니라 서버 API에서도 권한을 확인하도록 구현했습니다. 축제 설정은 권한에 맞는 항목만 보여주되 저장 버튼은 하나로 통합했습니다.

운영진 지정과 업무별 권한 변경·회수 기능을 구현했습니다. 두 차례 축제 운영 경험을 바탕으로 고도화하고 있으며, 기존 서버 운영을 종료한 상태에서 2026년 11월 재배포와 졸업작품 시연을 준비하고 있습니다.

03

현재 상태

권한 관리 구현 완료 · 2026년 11월 재배포 준비

기기·브라우저별 출시 전 검증

학생용 화면은 아이폰 Safari와 갤럭시의 구글 앱 등에서 직접 확인했습니다. 관리자 화면은 총학생회가 요청한 노트북·태블릿 사용 비율을 고려해 제작하고 노트북의 Safari·Chrome·Edge·Firefox에서 점검했습니다.

당시 아이폰에서 홈 화면에 추가한 웹앱(PWA)을 실행했을 때는 Safari와 달리 당겨서 새로고침되지 않았습니다. 티켓팅 이용자가 직접 화면을 갱신할 수 있어야 한다고 판단해 별도 새로고침 버튼을 추가했습니다.

실서비스 운영 성과 및 문제 해결 문서화

봄축제 팀 서비스는 가입자 6,063명과 티켓 3,500장 매진을 기록했습니다. 이후 가을축제도 운영했습니다. 예매와 페이스사인 연계는 봄축제에서 수행한 사례입니다.

현장에서는 직접 관리자 화면으로 예매 정보를 조회하고 팔찌를 배부했습니다. 학생과 스태프로부터 편리했다는 반응을 들으며, 개발한 기능이 실제 업무에 쓰이는 모습을 확인했습니다. 현장에서 개발자가 직접 처리하던 운영진 권한 설정은 후속 기능으로 옮겼습니다.

개발환경의 로그인 문제를 추적한 뒤에는 기준 환경과 증상별 확인 항목, 쿠키·스토리지 점검 및 복구 절차를 문서로 공유했습니다. 이후 유사한 문제를 겪은 동료가 이 문서를 활용해 복구했습니다. 해결 과정을 팀이 다시 사용할 수 있는 자료로 남긴 경험입니다.

운영 장애 복구: 로그에서 DB와 영어 화면까지

운영 중 발견한 번역 누락 복구 / 실제 번역 대상과 신규 공지로 확인

봄축제에서 제기된 유학생의 이용 불편을 바탕으로 팀은 가을축제 서비스에 영어 지원을 도입했습니다. 운영 중 번역 누락을 발견한 후 번역 기능 구현 담당자와 협의한 뒤 복구를 맡았습니다.

Docker Compose로 구동한 서버의 로그를 확보하고 AI 도구와 원인을 분석했습니다. 번역된 영문이 MySQL 컬럼 길이를 초과하면 전체 저장이 롤백돼 같은 데이터를 반복 번역하는 상황이었습니다. AI를 활용해 컬럼을 확장하고 저장 트랜잭션을 행별로 분리했습니다.

처리 로그가 0으로 나온 뒤에도 AI의 제안에 따라 DB 잔여 데이터를 점검했습니다. 조회 조건을 실제 번역 대상과 맞추고 공백 데이터를 정리한 뒤 SQL로 미번역 대상 0건을 확인했습니다. 이어 새 공지의 자동 번역, 저장, 영어 화면 표시까지 검증했습니다.
