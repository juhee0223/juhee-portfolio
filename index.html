RocksDB에서 Compaction Style에 따른 성능 변화 분석

게재·발행
KCC 2025 / 2025-07-02
저자·역할
박주희, 신호진, Guangxun Zhao, 최종무
구분
제1저자 · KCC 2025 발표 · pp. 2500–2502

연구 질문

  • SST 파일을 병합·정리하는 Compaction 방식에 따른 읽기·쓰기 성능 변화
  • 처리율·지연시간·쓰기 증폭(WAF)·쓰기 정체(Write Stall)·실제 조회 성공 횟수 비교

실험 조건

  • Intel Core i7-1360P · 메모리 15GB · Samsung 1TB SSD · Ubuntu 22.04.5 LTS
  • RocksDB db_bench · 값 크기 4KB · 데이터 1,000만 건의 랜덤 쓰기 후 랜덤 읽기
  • 세 정책을 동일 조건으로 비교 · statistics 옵션으로 내부 지표 수집
동일 조건에서 비교한 RocksDB Compaction 정책별 결과
측정 항목LeveledUniversalFIFO
쓰기 작업 시간1,608.1초1,091초533.7초
쓰기 증폭 (WAF)4.503.431.56
읽기 처리율약 8.41만 ops/s약 6.47만 ops/s약 260만 ops/s
실제 조회 성공 횟수7,134,622회7,005,533회5,797회

쓰기 해석

  • Universal: Leveled 대비 Compaction 시간 약 39.8%·Write Stall 시간 약 48.5% 단축
  • FIFO: 파일 병합·정렬 생략에 따른 가장 낮은 쓰기 비용

읽기 해석

  • Leveled: Universal 대비 약 1.3배 높은 읽기 처리율
  • FIFO: Leveled·Universal 대비 약 99.92% 적은 실제 조회 성공 횟수
  • FIFO의 오래된 데이터 삭제 특성 · 높은 처리율을 실제 데이터 조회 성능으로 해석하기 어려움

의미·한계

  • Leveled: 읽기 중심 작업에 이점 · Universal: 쓰기 비용·읽기 성능의 균형에 이점
  • FIFO 선택 시 데이터 보존 요구 고려 · 처리율·지연시간·조회 성공 여부의 동시 평가 필요

후속 연구

  • 계층별 정책을 조합하는 Tiered Compaction 제안
  • 읽기·쓰기 혼합 워크로드 실험 제안
